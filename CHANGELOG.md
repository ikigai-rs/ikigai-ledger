# Changelog

## 0.26.4

- ⚠ **`wait` and `offers` are now reserved ledger names.** An existing ledger named `wait` or `offers` becomes unreachable on upgrade (`urn:iki:ledger:wait:item:5` is now item 5's queue in the default ledger), as with `stalled` and `lapse`. Rename such a ledger before upgrading.
- A fair claim queue (ledger #4455; the design is `docs/design/fair-claim-queue.md`): `urn:iki:ledger:{ledger}:wait:item:{id}` lists an item's live waiters in order (under `read:`), joins or renews a place (under `claim:` or `write:`; a free item nobody else is offered is claimed at once) and leaves one (with a release's principal rules). A release offers the item to the first live waiter in the same update, and the claim guard refuses anyone else while the offer stands; an offer nobody takes passes to the next waiter, written by the next claim, join or leave, or by the dispatcher's new `sink urn:iki:ledger:{ledger}:offers` (under `close:` or `write:`). `next` leaves an offered item out with `why: "offered"`, and takes `waiter=`. New vocabulary terms: `ledger:WaitPlace`, `ledger:waitsOn`, `ledger:waiter`, `ledger:waiterPrincipal`, `ledger:askedAt`, `ledger:waitSeq`, `ledger:waitExpires`, `ledger:waitPoll`, `ledger:offeredTo`, `ledger:offerExpires`, `ledger:offerAfterEpoch`. A claim under `close:` or `write:` (the dispatcher's override) passes a standing offer, voids it and names it on its claim event as `ledger:overrodeOffer`. An offer to a place that lapsed stands for nobody, and an ended offer passes to the next live waiter by one rule the claim guard, `next` and the queue's read share, whether or not a sweep has run. Closing an item removes its offer and its places in the same update, and a place a join added while the close was being written is taken once the close has landed, so no place outlives a close. Additive: a store written by an older release loads and behaves as before (`tests/claim_queue.rs`, over a 0.26.3 dump), and an empty queue changes nothing.
- The transition feed, the ledger's outbox (ledger #4116): `source urn:iki:ledger:{ledger}:transition after={n} limit={k} epoch={e}`, under the ledger's read grant. Each filing, claim, release, hand-back, lapse, close and reopen writes an immutable entry `…:transition:seq:{n}` in the same store update as the state it records, numbered from 1 in commit order per ledger, with the item, the kind, the item's claim epoch, the principal of the write and the authored time (for display only). The JSON face has the layer feed's shape, `{ledger, epoch, last, entries}`: `last` is how far the read got, so a follower moves past a gap, and a cursor past the head or from another feed epoch is refused as Conflict. Delete and purge leave the entries whole.
- `transition` is a reserved ledger name.
- Upgrade: a store written before this release starts its feed at head 0 with no backfill of earlier transitions; a ledger already named `transition` can no longer be reached by name.

## 0.26.3

- A `caused-by` link kind: a defect item can name the item that introduced it, in the same ledger or across ledgers (an informational link; it never blocks), with the vocabulary term `ledger:causedBy`, and a close can record its causes (ledger #4337).
- Search: an indexed phrase falls back to the RDF scan when a field holds a character the regex tables do not yet classify, so a phrase next to a newly assigned letter is still found; relevance lets the store tokenize the original query, so a word such as `İstanbul` scores above zero. Face and refusal text are unchanged.

## 0.26.2

- Refuse unreadable optional arguments instead of silently using defaults. Callers that sent an invalid value and previously received the default now receive a refusal. No persisted state changes.
